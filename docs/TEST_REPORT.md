# Test Report — PDF Test Designer 1.0.0

This report records what was tested, how, and the measured results. Nothing here is estimated.
Where something could not be tested in this build environment, that is stated explicitly.

## 2. Automated backend tests — 65 tests

Run with network access blocked: any non-loopback connection fails the run, which proves the
core works offline.

| Area | Tests |
|---|---|
| One-click generation on realistic documents (`test_generate.py`) | 11 parametrised cases, each verifying: A4 page size; searchable text; every question's wording and options identical to the source; every question present in the PDF **in order**; all images placed; nothing outside page bounds; fonts embedded; compressed copy and thumbnails produced; original file untouched. Also: page count, 100-question numbering, Uzbek characters (oʻ, gʻ, ʼ, curly quotes, em dash), scanned PDF flagged (never claimed perfect), multi-column order, Word auto-numbering, multiple page layouts in one document, **batch of ten** + ZIP, batch failure isolation + retry, custom fonts embedded (no base-14 fonts), idempotency, regenerate never overwrites, edited content used on regenerate, automatic numbering leaves stored content unchanged, Mode B original pages (branding added, every original word kept), page reorder/rotate/exclude, export variants (grayscale, selected pages, sections, PNG pages, JSON, compressed) |
| Validation engine (`test_validation.py`) | proven by **sabotage**: deleted question, missing option, swapped order, missing image, unsupported characters and incomplete extraction are all detected as critical; page numbers present; no blank pages or orphaned headings; oversized question split and reported (never dropped); a 9-column, 120-row table fits the width and repeats its header on every page |
| Storage, API, security (`test_store_api.py`) | seeded templates and branding, template CRUD and validation, versions + restore, trash/restore/permanent delete, original stored read-only, backup → delete → restore, interrupted-job recovery after a crash, token auth (401) and Host-header check (403), full HTTP quick-generate flow with six real steps, unsupported uploads (.exe, legacy .doc), model editing + preview, template import/export, built-in templates protected, logo/SVG assets (scripted SVG rejected), image crop/rotate/flip/opacity, font upload, OTF→TTF conversion |
| Explorer engine (`test_shell.py`) | Unicode and space-containing file names, very long names, mixed PDF+DOCX+TXT multi-select with a picked template, folders with/without subfolders (skips unsupported and `~$` lock files), failure isolation, compress, grayscale (pixel-verified gray, text still searchable), document info, extract text+images, convert to DOCX, convert to PDF (unbranded), image → PDF, image as watermark/background applied to branding, clear errors (unsupported format, missing file, template not found, output folder unavailable), naming patterns + no-overwrite numbering, batch cancellation, API validation |

Result (Linux): **65 passed**.

During testing, an intermittent failure exposed a real race condition: two jobs writing the same
cached image at once. Cache writes are now atomic (write to a temp file, then rename).

### Visual inspection

Every generated page in `docs/test-report/*.png` was inspected. The inspection confirmed:
- the header logo and organisation name appear on every page;
- the cover pages show the candidate fields;
- the watermark sits behind the content at low opacity;
- options are laid out in 4-column, 2-column or vertical form depending on their length;
- the 69-row table repeats its header row on each continuation page;
- the full-page map stays on the same page as its heading (it shrinks rather than leaving a near-empty page);
- the two-column template flows correctly;
- no text is clipped and nothing sits outside the margins.

## 7. Not verified in this environment

* **Interactive testing on physical Windows 10 and Windows 11 desktops** (clicking through File
  Explorer, Windows 11 "Show more options", toast appearance). The CI exercises the same command
  lines and registry keys on Windows Server, but not Explorer's own UI.
* **The top-level Windows 11 context menu (IExplorerCommand)** — not implemented; it requires a
  code-signed sparse MSIX package (see `docs/WINDOWS_INTEGRATION.md`).
* **Code signing** — the installer is unsigned, so SmartScreen will warn on first run.
